## What Vex is

<CardGrid>
  <Card title="A formula at each record" icon="seti:grid">
    A Vex program evaluates at one key of a space of records. A field name reads at the focus. An address reads at another key, like a spreadsheet reference.
  </Card>
  <Card title="Axes" icon="random">
    The others axis evaluates a body at each other key. The base value comes from the origin, and the fields come from each target.
  </Card>
  <Card title="Error values" icon="warning">
    Vex does not throw. A failure is an error value with a code, for example `#REF!` or `#N/A`, and a trace shows where it started.
  </Card>
  <Card title="Your domains" icon="puzzle">
    A domain tells Vex which values belong to it, which ops they have, and which laws the ops obey. Tests check each law.
  </Card>
</CardGrid>

## Use it in your code

Install the core and the domains. Then build a chain over your own records. The chain has the type of its result.

```ts
import { space, vex } from "@mark1russell7/vex";
import { Vec2, Vec2Domain } from "@mark1russell7/vex-domains";

const A = { position: new Vec2(2, 2), size: new Vec2(5, 4) };
const B = { position: new Vec2(6, 5), size: new Vec2(4, 4) };

const separated = vex(Vec2Domain)
  .over(space.record({ A, B }))
  .from("position")._.add("size")
  .other()._.subtract("position")
  ._.anyNonPositive();

separated.at("A"); // { tag: "some", value: false }
separated.explain("A"); // a trace of each step
```

[The tour](learn/tour/) adds one call at a time to a chain. [The API](reference/api/) lists each export, and [the specification](spec/) shows the test status of each requirement.
