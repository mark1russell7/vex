The builder does not evaluate anything. It makes an expression: a tree of plain JSON data. The interpreter evaluates the tree. Other functions read the same tree: `explain` makes a trace, `deps` lists the reads, and `serialize` gives the JSON text.

## A program and its data

<ProgramIR program="nearest" />

The chain `others(...)` binds the current value to a fresh name (`$0`), and the body reads that name with `var`. Thus the base value comes from the origin, and the field names of the body read at each target.

## The kinds of expression

| Kind | Fields | Value |
|---|---|---|
| `lit` | `value` | the value |
| `ref` | `path`, `at` | the field at the path, in the record at the address `at` |
| `app` | `op`, `args` | the op applied to the values of the arguments. For a method op, the first argument is the receiver. |
| `let` | `bind`, `body` | the body, with names bound to the values of the bindings |
| `var` | `name` | the value of a bound name |
| `fn` | `params`, `body` | a function. It is only a binding of `let`. |
| `call` | `fn`, `args` | the body of the bound function `fn` at this position, with the values of `args` for its parameters |
| `rec` | `fields` | a record of the values of the fields |
| `each` | `axis`, `body`, `at` | a list: the body at each target of the axis, from the key of the address `at` |
| `fold` | `axis`, `init`, `step`, `result`, `at` | a loop over the targets of the axis, in order. `init` gives the names and their first values, and `step` gives the next values at each target. |
| `iterate` | `limit`, `init`, `step`, `result`, `until` | a loop of at most `limit` steps (a whole number up to 100000). A true `until` stops it. |
| `ext` | `kind`, `data` | the value that the extension handler of `kind` gives |

The first three kinds have the same shape as the expressions of the `render` project. Thus a `render` expression is also a Vex expression.

The special forms `if`, `and`, `or` and `ifError` are `app` nodes. The interpreter evaluates their arguments only when it needs them.

## Functions

A binding of `let` can be a function: `fn(params, body)`. `call(name, ...args)` applies it. Write a calculation once, and call it where you need it.

```ts doctest
import { app, axes, call, each, evaluate, fn, let_, lit, ref, space, v } from "@mark1russell7/vex";
import { NumDomain } from "@mark1russell7/vex-domains";

const rows = space.array([{ w: 10 }, { w: 20 }, { w: 30 }]);
// The body reads the field w at the position of the call: here, at each target of the axis.
const weight = fn(["k"], app("multiply", ref("w"), v("k")));
const total = let_({ weight }, app("sum", each(axes.all, call("weight", lit(2)))));

evaluate(total, { space: rows, origin: "0", domains: [NumDomain] }); // => { ok: true, value: 120 }
```

- The body evaluates at the position of the call. Thus a field reference of the body reads at the focus of the call.
- The body sees the names of the place of its binding, not the names of the place of the call.
- Each parameter gets the value of its argument. An argument that fails has an effect only where the body reads it.
- A function cannot call itself or another binding of its `let`. Thus each call ends. A function of an outer `let` is in the scope.
- A parameter, a binding or a name of a loop with the name of a function hides the function.
- A function is not a value. `v` of a function, a call of a value and a call with the wrong number of arguments give `#VALUE!`.

Tier 2 puts the body at each call, in at most 10000 places of one program. A module prints one JavaScript function for each function. Refer to the rules `FN.*` of [the specification](../../spec/).

## Addresses

An address is a list of moves. The moves apply in order, from the focus.

| Move | Goes to |
|---|---|
| `{ t: "key", key }` | the key, or `#REF!`. `key` can be an expression that gives a text. |
| `{ t: "index", i }` | the key at position `i` of the key order. `i` can be an expression that gives a number. |
| `{ t: "other" }` | the other key of a space with two keys |
| `{ t: "offset", d }` | a relative position in an array (one number) or a grid (two numbers) |
| `{ t: "origin" }` | the origin of the evaluation |
| `{ t: "parent" }` | the parent of the focus in a tree space |

Vex does not simplify an address. For example, `[other, other]` in a space with three keys gives `#REF!`. A simplification to the empty address hides that error, so Vex keeps each move.

## Axes

| Axis | Targets |
|---|---|
| `{ t: "all" }` | each key |
| `{ t: "others" }` | each key except the focus |
| `{ t: "other" }` | the other key of a pair |
| `{ t: "neighbors", n }` | the 4 or 8 neighbor cells of a grid |
| `{ t: "children" }`, `{ t: "ancestors" }`, `{ t: "descendants" }`, `{ t: "siblings" }` | the relations of a tree space. Refer to [trees](../../learn/axes/#trees). |
| `{ t: "window", from, to }` | the keys at the offsets from `from` to `to`, in an array or among siblings |
| `{ t: "successors" }`, `{ t: "predecessors" }`, `{ t: "reachable" }` | the edges of a graph space |
| `{ t: "table", name }` | each key of another table of the evaluation |
| `{ t: "list", list }` | the keys of the items of the list that the expression `list` gives, in the order of the list |
| `{ t: "reverse", axis }` | the targets of `axis` from the last to the first. The inner axis is not `where`, `reverse` or `table`. |
| `{ t: "where", axis, test }` | the targets of `axis` where `test` gives `true` |

## Lists as values

The value of `each` is a list: one item for each target, with its key and its result. A `let` can bind a list, and a list op applies to its name. The axis `list(expr)` has the keys of the items of a list as targets, in the order of the list. The body reads the fields of each target.

```ts doctest
import { app, axes, each, evaluate, let_, lit, ref, space, v } from "@mark1russell7/vex";
import { NumDomain } from "@mark1russell7/vex-domains";

const boxes = space.array([{ x: 30, w: 1 }, { x: 10, w: 2 }, { x: 20, w: 3 }]);
// The boxes in the order of x, and then the widths in that order.
const byX = let_({ sorted: app("sortBy", each(axes.all, ref("x"))) }, app("values", each(axes.list(v("sorted")), ref("w"))));

evaluate(byX, { space: boxes, origin: "0", domains: [NumDomain] }); // => { ok: true, value: [2, 3, 1] }
```

| Op | Value |
|---|---|
| `sortBy(list)` | a list with the items in the order of their values, from the smallest. The values are numbers or texts. Equal values keep their order. |
| `take(list, n)` | a list of the first `n` items |
| `nth(list, i)` | the value of the item at the position `i`, from 0. A position after the last item gives `#N/A`. |

These ops skip error items, as each list op does. The option `{ strict: true }` gives the first error. The axis `reverse(list(expr))` gives the reverse order, and an error item of the list gives an error item for its target. The compiler does not have lists as values yet, so tier 1 evaluates such a program.

## Programs are data

<ProgramIR program="overlaps" />

A program can go to a file, a database, a worker or another process. The JSON Schema of the IR is at [`ir.schema.json`](../../ir.schema.json), and a test keeps it equal to the checks of `parse`. A language model can write a program from the schema, and [`llms.txt`](../../llms.txt) tells it where to start. `serialize` gives the JSON text, and `parse` checks the tree when it reads it back. A literal that is a domain value needs `encode` and `decode` in its domain.

`compile(expr, options)` changes the tree into a tree of functions, once. The program then evaluates at each origin of each space without a new walk of the tree. `evaluate` uses `compile` too, so the two cannot give different results.

`deps(expr)` gives each field read of a program, with its address, the axes around it and the address of each axis. A host can use the reads to evaluate a program again only when a field that it reads changes. Refer to [the Lab](../../lab/) to change a program as JSON.
