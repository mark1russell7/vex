A domain tells Vex which values belong to it and which ops they have. The tables below come from the domain objects of `@mark1russell7/vex-domains`, at the time of the build. Thus the tables and the code are the same.

- **parameters**: the kinds of the arguments after the receiver. The interpreter checks them, and an argument of the wrong kind gives `#VALUE!`. "not checked" means that the op does not declare its parameters.
- **laws**: the claims of the op. The law checker of `@mark1russell7/vex-testkit` tests each claim with random values. Refer to [the law arena](../../gallery/laws/).
- **lifts numbers**: a number argument becomes a domain value with `fromScalar`. For example, `add(5)` adds the vector (5, 5).
- **identity**: the value that `reduce` gives for an empty list.
- **implementation**: `method` calls the method of the value with the same name. `fn` calls a function of the domain.

## Dates

A `LocalDate` is a day of the calendar, without a time and without a time zone. It keeps the count of days since 1970-01-01. Thus a date plus a number is a later date, and a date minus a date is a count of days. The op `date` of `NumDomain` makes a date from a year, a month and a day. A month or a day outside its range rolls over, like `DATE` of a spreadsheet.

```ts doctest
import { DateDomain, LocalDate, NumDomain } from "@mark1russell7/vex-domains";

const bills = vex(NumDomain, DateDomain).over(space.array([{ issued: LocalDate.of(2026, 9, 1), terms: 30 }]));
const due = bills.from("issued")._.add("terms");

due.at("0");                          // => some(LocalDate.of(2026, 10, 1))
LocalDate.of(2026, 13, 1).toString(); // => "2027-01-01"
```

`addMonths` and `endOfMonth` move by months, like `EDATE` and `EOMONTH`. One month after 31 January is the last day of February.
